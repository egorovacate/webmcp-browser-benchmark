# Отчет: почему «visual лучше webmcp» — артефакт, и самопрогон T1–T5

Дата: 2026-10-10. Автор прогона: Muse Spark (скриптованный самопрогон, без подписки Codex).

## 1. Проблема

В подписочных замерах появилось «невозможное» данное: visual (div-клики) дешевле webmcp.

## 2. Диагностика старых логов

- Батч `2026-10-09T20-25`, visual/T1 — **55 124 токена**: проваленная попытка. Тред не читал страницу измеряемыми DOM-инструментами (утечка `cua_repl`), ответ «Unable to access Chrome», оракул провален. Это диагностический расход, а не измерение. Сравнение его с успешным webmcp (72 428) и дало иллюзию.
- Валидные завершенные замеры из разных батчей: webmcp **72 428** total против visual **87 809** total — webmcp дешевле, как и должно быть. Замороженного сравнения «3 режима в одном батче» нет.
- Ловушка uncached-токенов: visual 14 163 < webmcp 18 070. Это шум промпт-кэша Codex в единичных сэмплах; биллируемая метрика — total (input + output) внутри одного батча.
- Свежий `bun run benchmark T1` (2026-10-09T23-49): все 3 режима упали одинаково — `You've hit your usage limit ... try again at Oct 14th, 2026`. Стенд отработал корректно: failed-диагностика, без липовой таблицы. Квота — единственная причина отсутствия новых цифр.

## 3. Самопрогон T1–T5: токены, колы, время (без модели)

Метод: скриптованные маршруты, токенизация `o200k_base`. Input = точные схемы MCP-инструментов (webmcp 443, visual 361, playwright 797 — сняты с живых серверов) + точные байты наблюдений; у webmcp добавлен хост-оверхед (new_page + list_webmcp_tools, +2 кола). flowMs — машинное время без инференса модели. **Output и reasoning — n/a: их производит только живой вызов модели** (заблокирован квотой до 14 октября). Единственные настоящие output/reasoning — из старых подписочных логов T1: webmcp 342/61, visual 430/117, playwright 810/294.

## 4. Найденный косяк стенда и фикс

T5 через чистый DOM был **невыполним**: в корзине не было кнопок количества/удаления, а обход через quantity=0 молча блокировался нативной валидацией формы (`min="1"`, submit не срабатывает). Старая цифра «Visual T5 completed» — из прежнего харнеса, на замороженном UI невоспроизводима.

Фикс (выбран вариант 1): кнопки − / + / Remove на каждой строке корзины (`src/web/App.jsx`, `src/web/styles.css`), через существующий `PUT /api/cart/items` (0 = удалить). WebMCP-тулы не менялись. После фикса T5-DOM проходит (29 вызовов, оба оракула).

## 5. Статус тестов после фикса

Юниты 62/62, браузерный стор, DOM-рантайм, Pages-демо — все зеленые.
